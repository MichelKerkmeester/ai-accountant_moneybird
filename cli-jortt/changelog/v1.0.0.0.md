# cli-jortt v1.0.0.0: Initial Release

This release adds a standalone Jortt skill that reads source records for a Moneybird migration and keeps every saved extract out of tracked files.

&nbsp;

## Why This Release

Jortt has a REST API but no official CLI. The skill adds a local OpenAPI-driven CLI so an agent can find operations, page through records and save results to a gitignored workspace without risking a write.

&nbsp;

## What's New at a Glance

- **`jortt-cli` covers every operation in the local Swagger document.** It derives stable slugs and checks parameter names, types and enums before a request.
- **Writes stay locked by default.** A non-GET call needs `--allow-write` and the matching scope in `JORTT_SCOPES`, and both checks run before a token exists.
- **Paged lists arrive as one file.** `--all` follows next links and merges each page into one JSON array.
- **Saved output cannot leave the workspace.** `--out` and signed downloads resolve only inside `migration-workspace/`.
- **UI-only records are named honestly.** XAF auditfiles, annual accounts and filed VAT returns go to the operator, and no general ledger export is promised.
- **A feature catalog and an operator playbook ship with the skill.** Each scenario links to the catalog entry it validates. Offline CLI tests cover slugs, gates and output paths. No benchmark runs are recorded yet.

&nbsp;
