# REF-002 -- Reference index and year changes

This document captures the offline prompt, local read sequence, expected signals and evidence for REF-002.

---

## 1. OVERVIEW

This scenario validates the reference index and year changes generator. It focuses on running the check mode, which recomputes every generated block in memory and reports drift without writing.

### Why This Matters

One pass over the reference tree owns the index, the year README tables, the year-figure rows of the general topic files, the change blocks and the year changes overview. A hand edit inside a generated block or a stale table would leave the tree disagreeing with itself, so the check holds every generated byte against its owning file.

---

## 2. SCENARIO CONTRACT

- Objective: Run the reference index check and report whether the generated blocks stay in step with the files that own them.
- Real user request: Run the reference index check and tell me whether the year README tables, the year change blocks and the overview are in step with the files that own them. Keep this offline.
- Prompt: Run the reference index check and tell me whether the year README tables, the year change blocks and the overview are in step with the files that own them. Keep this offline.
- Fixture rows: none in routing-gold.json. The check runs on the real corpus.
- Expected execution process: Read the project bootstrap and skill, run the check mode, read the ok line, name the generated outputs and the fence rule, confirm nothing was written and confirm no network call.
- Expected signals: The check prints `reference-index: ok`, the report names the generated outputs index.json, the year README tables, the general topic rows, the year change blocks and year-changes.md, names the marker fence rule and the reachability report, confirms no file was written and the run makes no network call.
- Desired user-visible outcome: The ok line, the named outputs and fence rule and a clear PASS or FAIL verdict.
- Pass/fail: PASS if the check exits 0 and prints `reference-index: ok`, no file was written and the report names the outputs and the fence rule. FAIL if the check reports drift or a bullet failure, exits nonzero, writes a file or the response makes a network call.
