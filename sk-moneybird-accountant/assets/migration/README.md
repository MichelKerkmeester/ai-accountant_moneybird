# Migration plan kit

Placeholder templates for a 23-phase Jortt to Moneybird migration, plus the scripts that turn them into a working plan. This folder and the template packet hold no real values. Every filled copy lives in a git-ignored folder at the repository root.

## 1. OVERVIEW

The migration runs phases 0 to 22. Each phase has a contract with eleven fields in `references/migration/`. The generator turns those contracts into a spec-kit template packet at `specs/000-migration-template/` in the repository root: a phase parent with its goal plus one Level 3 packet per phase. Each phase packet holds `spec.md`, `plan.md`, `tasks.md`, `acceptance-criteria.md`, `decision-record.md`, `implementation-summary.md` and a nested `goal.md`. `scripts/init-workspace.sh` copies that packet to a git-ignored working packet and builds `migration-workspace/` from the files in this folder. Work in the copies. Never fill or commit the templates.

---

## 2. ASSETS

Generated by `scripts/generate-plan-kit.py`:

- `specs/000-migration-template/` at the repository root. The parent `spec.md` and `goal.md`, and 23 child folders named `NNN-phase-N-<slug>`, rendered from the templates in `spec-template/`. The docs carry the phase contract text and bracketed placeholders such as `[YYYY-MM-DD]` and `[evidence path in migration-workspace/]` for your own context.
- `migration-config.template.json`. One entry per required `MIGRATION_CONFIG` field from `references/migration/overview-and-setup.md`, every value `PENDING`.
- `phase-dashboard.template.md`. The 23-row master phase table for M9 in `references/migration/shared-mechanisms.md`.
- `workspace-folders.txt`. The folder list that `scripts/init-workspace.sh` creates. Comment lines start with `#`.

Hand written:

- `spec-template/`. The nine packet doc templates the generator renders, two for the parent and seven for each phase.
- `run-journal-event.template.json`. An example run journal event with every M3 field, the allowed journal states, and placeholder values.
- `README.md`. This guide.

## 3. HOW TO USE

1. Run `scripts/init-workspace.sh --dry-run` to see what would happen, then `scripts/init-workspace.sh` from the repository root. The script refuses to run unless git ignores both target folders.
2. It creates `migration-workspace/` at mode 700 and copies the config template to `MIGRATION_CONFIG.json`, the dashboard to `Plans/phase-dashboard.md` and the run journal template to `RunJournal/run-journal-event.template.json`. It creates an empty `RunJournal/run-journal.jsonl` when that file is missing.
3. It copies `specs/000-migration-template/` to `specs/001-migration/`, renames the packet in every doc, drops the generated notice and adds a `scratch/` folder to each packet. Pass `--spec-name 002-my-books` to choose another name.
4. Existing files are never overwritten. A second run skips every file it already copied.
5. Work each phase from its packet in the working copy. Fill the placeholders with your own context and keep evidence in `migration-workspace/`. The packet docs hold status, counts and evidence paths only, never personal or financial records. Filled copies are never committed.

---

## 4. KEEPING THEM IN SYNC

Generated files come from `references/migration/phases-*.md`, `references/migration/phase-22-completion.md`, the config table and workspace layout in `references/migration/overview-and-setup.md`, and the templates in `spec-template/`. `python3 -I scripts/generate-plan-kit.py --check` writes nothing and exits 0 when every generated file matches. It exits 1 and lists each file that is missing, different or unexpected. Regenerate after changing a reference or a template. A template may place a long contract field only once, alone on its own line, and the generator stops with an error otherwise. The `description.json` and `graph-metadata.json` files in the template packet come from the spec-kit tooling, not from the generator. Run `scripts/plan-kit-test.sh` for the full suite, or `scripts/plan-kit-test.sh path/to/sk-moneybird-accountant` to test another copy of the skill. Editing a generated file by hand makes the check fail until the generator runs again.
