# Migration plan kit

Placeholder templates for a 23-phase Jortt to Moneybird migration, plus the scripts that turn them into a working plan. This folder holds no real values. Every filled copy lives in the git-ignored `migration-workspace/` at the repository root.

## 1. OVERVIEW

The migration runs phases 0 to 22. Each phase has a contract with eleven fields in `references/migration/`. This folder turns those contracts into fill-in plans and one config template, and `scripts/init-workspace.sh` copies them into `migration-workspace/`. Work in the workspace copies. Never fill or commit the templates in this folder.

---

## 2. ASSETS

Generated by `scripts/generate-plan-kit.py`:

- `phases/phase-NN-plan.md` for phase 00 to 22. The working copy of one phase contract, with a status table, the nested sub-goals as checkboxes, the numeric exit gate, and a run record.
- `migration-config.template.json`. One entry per required `MIGRATION_CONFIG` field from `references/migration/overview-and-setup.md`, every value `PENDING`.
- `phase-dashboard.template.md`. The 23-row master phase table for M9 in `references/migration/shared-mechanisms.md`.
- `workspace-folders.txt`. The folder list that `scripts/init-workspace.sh` creates. Comment lines start with `#`.

Hand written:

- `run-journal-event.template.json`. An example run journal event with every M3 field, the allowed journal states, and placeholder values.
- `README.md`. This guide.

---

## 3. HOW TO USE

1. From the skill folder, run `python3 -I scripts/generate-plan-kit.py` to refresh the generated assets. Add `--check` to compare without writing.
2. Run `scripts/init-workspace.sh --dry-run` to see what would happen, then `scripts/init-workspace.sh` to create `migration-workspace/` at the repository root. The script sets mode 700 on the workspace and refuses to run unless git ignores the folder.
3. The script copies the config template to `MIGRATION_CONFIG.json`, the dashboard to `Plans/phase-dashboard.md`, the 23 phase plans to `Plans/`, and the run journal template to `RunJournal/run-journal-event.template.json`. It creates an empty `RunJournal/run-journal.jsonl` when that file is missing.
4. Existing files are never overwritten. A second run skips every file it already copied.
5. Fill the copies in the workspace and keep evidence paths in the workspace too. Filled copies are never committed.

---

## 4. KEEPING THEM IN SYNC

Generated files come from `references/migration/phases-*.md`, `references/migration/phase-22-completion.md`, and the config table and workspace layout in `references/migration/overview-and-setup.md`. `python3 -I scripts/generate-plan-kit.py --check` writes nothing and exits 0 when every generated file matches. It exits 1 and lists each file that is missing or different. Regenerate after changing a reference. Run `scripts/plan-kit-test.sh` for the full suite, or `scripts/plan-kit-test.sh path/to/sk-moneybird-accountant` to test another copy of the skill. Editing a generated file by hand makes the check fail until the generator runs again.
