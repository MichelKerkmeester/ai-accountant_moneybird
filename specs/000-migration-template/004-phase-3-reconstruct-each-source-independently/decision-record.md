### Context

Phase 3 moves books from Jortt (system of record until the migration is signed off) into Moneybird (system of record after it). Every write on the Moneybird side touches the live administration of a Dutch sole trader, so a mistake is not a private bug. It lands in the books.

The phase contract is [phases-3-to-5.md](../../../sk-moneybird-accountant/references/migration/phases-3-to-5.md) and the shared mechanisms are [shared-mechanisms.md](../../../sk-moneybird-accountant/references/migration/shared-mechanisms.md).

### Constraints

- Jortt stays read-only for this phase, reads and exports only.
- Moneybird writes only through moneybird-guard, and each write pauses at the Operator gate.
- Evidence stays in the ignored migration-workspace/, bookkeeping records stay in the administrations.

### Decision

**We chose**: keep Jortt read-only and route every Moneybird write in Phase 3 through moneybird-guard, pausing at each Operator gate.

**How it works**: each Operator gate in this phase gets a numbered entry below with a decision, an approver, a date and an evidence path. A PENDING entry blocks the exit gate until the Operator signs it.

### Alternatives Considered

| Option | Pros | Cons | Score |
|--------|------|------|-------|
| **Route writes through moneybird-guard with Operator gates** | Every write is reversible, every gate leaves a decision trail, and the Operator keeps control | One extra stop per write and a wait on the Operator | 9/10 |
| Manual entry straight into Moneybird | Fast for a single entry and no tooling needed | No gate and no trail. Mistakes land in the live books | 3/10 |
| Bulk import with the guard switched off | Moves volume in one run | Skips the gates this migration exists for | 2/10 |

**Why this one**: the guard route is the only option that keeps the phase exit gate and the Operator approval meaningful for the whole migration.

<!-- ANCHOR:adr-001-consequences -->
### Consequences

**What improves**:
- Every write in this phase can be traced to a gate and a decision entry.
- Mistakes are caught before they reach the live administration.

**What it costs**:
- Each write waits on an Operator gate. Mitigation: batch related entries so one gate covers a group.
- Evidence capture adds a step after each gate. Mitigation: the phase tasks bundle it once per phase.

**Risks**:

| Risk | Impact | Mitigation |
|------|--------|------------|
| A gate is skipped under time pressure | H | CHK-010 fails the phase and the write is compensated |
| Guard is unavailable mid phase | M | The stop condition triggers and the phase pauses for the Operator |
| Evidence is lost before sign-off | L | Evidence lands in migration-workspace/ and is named in the decision entries |
